# Quiz — приложение для аттестации

Веб-приложение для назначения и прохождения учебных тестов. Проект вырос из
консольных домашних работ репозитория
[`2024-03-otus-spring`](https://github.com/alex-samusenko/2024-03-otus-spring)
и сохраняет их предметную модель и сервисы проверки ответов. Основным
хранилищем пользователей, тестов и банка вопросов является база Moodle.

## Возможности

- вход под одной из четырёх ролей: администратор, менеджер, преподаватель или слушатель;
- чтение тестов и вопросов из базы Moodle (локально — из её PostgreSQL-имитации);
- назначение теста слушателю и контроль статуса назначения;
- прохождение теста с одиночным и множественным выбором;
- сохранение ответа после каждого шага и ограничение времени;
- автоматический подсчёт баллов, проходного результата и разбор ошибок;
- отчёты по попыткам для менеджера и преподавателя;
- хранение пользователей, назначений и попыток в PostgreSQL;
- русскоязычный адаптивный интерфейс React.

## Запуск

Понадобятся Java 17+, Maven 3.9+ и Docker.

```bash
docker compose up -d
mvn spring-boot:run
```

После запуска приложение доступно по адресу <http://localhost:8080>.

Демонстрационные учётные записи:

| Логин | Роль |
| --- | --- |
| `admin` | администратор |
| `manager` | менеджер |
| `mentor` | преподаватель |
| `petrov` | слушатель |
| `user` | слушатель |

Пароль для всех демонстрационных записей: `1`.

## Разработка интерфейса

Собранная версия интерфейса уже включена в Spring Boot-приложение. Для работы
с React в режиме разработки:

```bash
cd frontend
npm install
npm run dev
```

Vite проксирует запросы `/api` к приложению на порту `8080`. После изменения
интерфейса выполните `npm run build` и перенесите содержимое `frontend/dist`
в `src/main/resources/static`.

## Проверка

```bash
mvn test
```

## Развёртывание через Docker Compose

Для production-сервера используется отдельный Compose-файл. PostgreSQL доступен
только приложению внутри Docker-сети, а веб-интерфейс публикуется на порту 80.

```bash
cp .env.example .env
# Замените POSTGRES_PASSWORD в .env на длинный случайный пароль.
docker compose -f compose.prod.yml up -d --build
```

Проверка состояния и просмотр журналов:

```bash
docker compose -f compose.prod.yml ps
docker compose -f compose.prod.yml logs -f application
```

Тесты используют H2 и не требуют запущенного PostgreSQL.

## Структура

- `src/main/java/ru/galaktika/web` — REST API, авторизация и сценарии работы;
- `src/main/java/ru/galaktika/db` — доступ к PostgreSQL и миграция схемы;
- `src/main/java/ru/galaktika/domain` — вопросы, ответы и результаты;
- `src/main/resources/db/moodle-question-bank.sql` — таблицы банка вопросов;
- `src/main/resources/db/moodle-question-seed.sql` — демонстрационные тесты;
- `src/main/resources/db/moodle-real-topic-autonomous-forms.sql` — реальный пример из Moodle: курс 375, категория 1785, восемь вопросов темы «Автономные формы»;
- `docs/moodle-import-postgresql.sql` — перенос тестов из Moodle 4.x/5.x;
- `docs/moodle-import.md` — инструкция и ограничения импорта;
- `frontend` — исходный код React-интерфейса;
- `docker` — инициализация демонстрационной базы Moodle.

# Эмулятор входа Moodle

На тестовом стенде доверенный переход можно проверять без развёртывания Moodle. Задайте
`MOODLE_AUTH_ENABLED=true`, `MOODLE_AUTH_EMULATOR_ENABLED=true` и случайный
`MOODLE_AUTH_SHARED_SECRET` длиной не менее 32 символов. На странице входа появится выбор
тестовой роли. Эмулятор формирует и тут же проверяет тот же HMAC-подписанный одноразовый
запрос, который используется endpoint `POST /api/moodle/launch`.

В продуктивной среде задайте `MOODLE_AUTH_EMULATOR_ENABLED=false`: endpoint эмулятора
вернёт 404, а доверенный переход из Moodle продолжит работать.
